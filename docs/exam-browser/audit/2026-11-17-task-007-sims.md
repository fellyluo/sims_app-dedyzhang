# Audit keamanan — SIMS, integrasi B'tive Exam Browser (fitur 02 TASK-007)

- Tanggal: 2026-11-17 · Checklist: `laravel-security-audit` (8 area) · SIMS single-tenant (tanpa `school_id` di tabel ujian)
- Lingkup: `WajibExamBrowser`, `UjianSiswaController::submit` (finish + token), `UjianController::update` (field `exam_browser_*`), migration `ujians`, `pengaturan.blade.php`, `kerjakan.blade.php` (`_ebHeaders`), `routes/web.php`, SDK `btive/exam-browser`, `.env.example`. Jalur yang **bisa melewati** kontrol baru (backup/restore ujian) ikut diperiksa.
- **Hanya audit — tidak ada kode yang diubah.** Semua temuan dibuktikan dengan 6 probe test sementara (P1–P6), lalu probe dihapus.

## Temuan

### [CRITICAL] C1 — Siswa bisa me-restore backup ujian: mengubah nilai sendiri & mencabut syarat Exam Browser  `[Pasti]`

`app/Http/Controllers/UjianBackupController.php:45-122` + `routes/web.php:1277`

- Route `POST /ujian/restore` berada di grup `modul:ujian` tanpa pembatasan role; `restore()` **tidak memanggil `authorize()`** dan memakai `Model::unguard()` + `updateOrCreate()` dengan isi file JSON apa adanya untuk `ujians`, `ujian_paket`, `ujian_soal`, `ujian_kelas`, `ujian_attempts`, `ujian_jawaban`, `ujian_pelanggaran`.
- **Probe P2:** login sebagai siswa, unggah JSON berisi `uuid` ujian + attempt miliknya → HTTP 302, `exam_browser_level` = NULL, `judul` = "DIRETAS", `skor_objektif` = 100.00, `status` = dinilai.
- Dampak: manipulasi nilai (alur nilai), menghapus pelanggaran, mengubah kunci jawaban (`is_benar`), dan mematikan syarat Exam Browser — termasuk untuk ujian milik guru lain.
- **Bukan dari TASK-007** (sudah ada sebelumnya), tetapi meniadakan kontrol baru dan menyentuh alur nilai.

Patch (tanpa migration):

```php
// routes/web.php — pindahkan restore & backup ke grup role pengelola
Route::post('/restore', [\App\Http\Controllers\UjianBackupController::class, 'restore'])
    ->middleware('role:admin,kurikulum')->name('restore');
```

```php
// UjianBackupController::restore() — paling awal
$user = $request->user();
abort_unless($user && ($user->isAdmin() || $user->canAccess('manage_ujian')), 403);

$request->validate([
    'password'    => 'required|string',
    'backup_file' => 'required|file|max:20480|mimetypes:application/json,text/plain',
]);

// ...setelah decode:
$existing = Ujian::withTrashed()->find($data['uuid']);
if ($existing) {
    $this->authorize('manage', $existing);
}
```

Disarankan juga (perubahan perilaku → perlu keputusan FL): hapus `Model::unguard()` dan pakai whitelist kolom per tabel; **jangan** me-restore `ujian_attempts`/`ujian_jawaban`/`skor_*` lewat unggahan file (atau batasi ke super admin + catat di log aktivitas).

### [MEDIUM] M1 — Sesi Exam Browser tidak diikat ke siswa/attempt SIMS  `[Kemungkinan Besar]`

`app/Http/Middleware/WajibExamBrowser.php:34-41`

- Verifier hanya memastikan header berasal dari sesi Exam Browser yang aktif dengan level cukup; tidak ada ikatan ke user SIMS yang login atau ke attempt. **Probe P1:** sesi Console dengan `peserta_ref` siswa lain → HTTP 200.
- Eksploitasi butuh header sah milik sesi lain (kunci sesi ada di perangkat itu; JS API `sign()` hanya untuk halaman ber-whitelist) → praktis perlu perangkat di-root (maks L1) atau XSS di SIMS. Untuk ujian L2/L3 risikonya rendah; untuk L1 sedang.

Patch (**GATE — migration**): simpan `ujian_attempts.eb_client_session_id` pada verifikasi sah pertama di `kerjakan`, lalu tolak (enforce) atau catat (report) bila sesi berbeda di request berikutnya — pindah perangkat sah lewat reset attempt oleh pengawas.

```php
// WajibExamBrowser::handle(), setelah $result->ok()
$attempt = $request->route('attempt');
if ($attempt instanceof \App\Models\UjianAttempt && $result->session) {
    if ($attempt->eb_client_session_id === null) {
        $attempt->forceFill(['eb_client_session_id' => $result->session->sessionId])->save();
    } elseif (! hash_equals($attempt->eb_client_session_id, $result->session->sessionId)) {
        $result = new \Btive\ExamBrowser\VerificationResult('eb_wrong_session', $result->session, $result->requiredLevel);
    }
}
```

### [MEDIUM] M2 — Mode enforce: Console mati → semua penyimpanan jawaban ditolak 503  `[Pasti]`

`app/Http/Middleware/WajibExamBrowser.php:57-63`

- **Probe P5:** Console tidak terjangkau → `sinkron-batch` HTTP 503. Jawaban tetap di `localStorage` perangkat dan diulang, tetapi selama Console mati seluruh ujian ber-Exam Browser berhenti tersimpan di server dan tombol Kumpulkan gagal ("server sibuk"). Satu gangguan Console = gangguan semua sekolah.

Patch (tanpa migration): fail-open **hanya** untuk XHR penyimpanan pada attempt yang sebelumnya sudah lolos verifikasi di sesi login yang sama.

```php
// Saat $result->ok() pada attempt ini:
$request->session()->put('eb_ok.'.$attempt->uuid, now()->timestamp);

// Sebelum menolak:
$attempt = $request->route('attempt');
$pernahLolos = $attempt instanceof \App\Models\UjianAttempt
    && $request->session()->has('eb_ok.'.$attempt->uuid);
if ($result->code === 'eb_console_unavailable' && $pernahLolos
    && $request->routeIs('ujian.siswa.jawab', 'ujian.siswa.sinkronBatch', 'ujian.siswa.submit')) {
    Log::warning('Ujian: Console tidak terjangkau, penyimpanan diteruskan (fail-open terbatas)', ['ujian' => $ujian->uuid]);
    return $next($request);
}
```

### [LOW] L1 — Status Console (dikunci/dikeluarkan) baru berlaku di SIMS setelah cache habis  `[Pasti]`

SDK `HttpIntrospector` (cache 120 detik). **Probe P4:** setelah sesi dikunci di Console, `kerjakan` dan `kumpul` tetap HTTP 200 sampai cache kedaluwarsa. Aplikasi Exam Browser sendiri tetap menampilkan layar terkunci (perintah lewat telemetri), jadi dampak terbatas.
Patch: set `EXAM_BROWSER_CACHE_TTL=30` di `.env` SIMS (tambahkan ke `.env.example`).

### [LOW] L2 — POST `mulai` dari browser biasa memulai attempt (dan waktunya) saat enforce  `[Pasti]`

`routes/web.php` (route `siswa.start` tanpa `exam.browser`, disengaja karena WebView tak bisa memberi header pada form POST). **Probe P3:** HTTP 302, attempt dibuat. Siswa hanya merugikan dirinya (waktu berjalan, `kerjakan` tetap ditolak).
Patch: di `WajibExamBrowser`, saat GET `siswa.gate` lolos, simpan `session(['eb_gate.'.$ujian->uuid => now()->timestamp])`; di `UjianSiswaController::start()` tolak bila ujian wajib + `enforce` dan penanda tidak ada/lebih dari 10 menit.

### [LOW] L3 — `trustProxies(at: '*')` memungkinkan `X-Forwarded-Host` palsu ikut membentuk URL kanonis  `[Pasti]`

`bootstrap/app.php:27` (sudah ada sebelumnya). **Probe P6:** header yang sah untuk host lain dengan path sama + `X-Forwarded-Host` palsu → HTTP 200. Butuh header sah dari sesi Exam Browser yang sama (milik siswa itu sendiri), jadi dampak kecil; tetapi `trustProxies('*')` juga memengaruhi `request()->ip()` (rate limit, log).
Patch: batasi ke IP proxy sebenarnya, mis. `$middleware->trustProxies(at: ['10.0.0.0/8', /* rentang Cloudflare/LB hosting */])`, atau jangan percaya `X_FORWARDED_HOST`.

### [LOW] L4 — URL Console tidak dipaksa HTTPS  `[Pasti]`

`config('exam-browser.console_url')` menerima `http://`. Bila salah konfigurasi, API key (`ebk_…`) dan `session_key` hasil introspeksi terkirim tanpa enkripsi.
Patch (SDK): di `ExamBrowserServiceProvider`, tolak/log error bila `console_url` bukan `https://` kecuali host `localhost`/`127.0.0.1`.

**Urutan eksekusi yang disarankan:**

1. **C1** — batasi route + `authorize` + validasi file restore (tanpa migration). Segera, terlepas dari Exam Browser.
2. **M2** — fail-open terbatas saat Console mati (tanpa migration) — **wajib sebelum beralih ke `enforce`**.
3. **L1** — `EXAM_BROWSER_CACHE_TTL=30`.
4. **L2**, **L4** — penanda gate & paksa HTTPS (tanpa migration).
5. **M1** — ikat sesi Exam Browser ke attempt — **GATE migration** (`ujian_attempts.eb_client_session_id`).
6. **L3** — batasi `trustProxies` (perlu tahu IP proxy hosting; konfigurasi lama).

Mode `enforce` sebaiknya baru dinyalakan setelah langkah 1–4 selesai dan masa uji `report` ≥ 1 minggu.
